# RepoLore.Cli 1.0.0-rc.1 (release candidate, no author signature)

Release candidate for 1.0.0: what 1.0.0 is planned to ship, published first so that it can be used on real work before the final cut.

## Install

```text
dotnet new tool-manifest
dotnet tool install RepoLore.Cli --version 1.0.0-rc.1 --local
```

A .NET 10 SDK is needed to install and a .NET 10.0.x runtime to run. See the [user guide](../user-guide.md).

## Changes since 0.1.0-preview.1

- **Changed:** the source-discovery rules file is now `.repoloreignore`; it was `_repoloreignore`. A leftover `_repoloreignore` is reported by `health-check` as a `policy-error` asking you to rename it. Its rules are not read, and it is no longer captured in history.
- **Documented:** an invalid rule in `.repoloreignore` is a blocking `policy-error` in `health-check`, but reads and writes continue, because ignore rules never decide what history protects.
- **Fix:** `init` writes the method and root templates with LF line endings whatever machine built the tool. A Windows build previously wrote CRLF. The published `0.1.0-preview.1` was built on Linux and was not affected.
- **Fix:** when `_repolore/.history` is a file instead of a directory, write commands now fail with a clear message naming the remedy. Before, they showed the runtime's raw message, which included the absolute path. The error ID is still `io-error`.
- **Security:** `SECURITY.md` describes a private reporting route through GitHub.
- **Package metadata:** it now carries the copyright line. The readme says "no author signature" and names the copyright holder.
- **Release files:** each release publishes a CycloneDX SBOM and a SHA-256 checksum file for the exact package and SBOM.
- **User guide:** it covers supported environments, how the privacy claim is evidenced, and how to verify a release.
- **Testing:** a scenario suite now replays a real user's history on a separate, append-only reference repository, on Windows, Linux and macOS, twice a week and before each release.

## Limits

- **No author signature.** NuGet.org adds only its own repository signature. Author signing is not planned for 1.0.0 (maintainer decision of 2026-10-24). This is not an enterprise-ready or certified release, and it makes no guarantee about what external editors or agents do with content they read.
- **Network evidence:** the networking-blocked run exists on Linux only, and there is no network-call trace.
- **Formats:** unknown knowledge formats are refused, and migration is explicit. The knowledge format is still 1.

## Verify

The publish run records the SHA-256 of the exact pushed package and of its SBOM in `RepoLore.Cli.1.0.0-rc.1.sha256`, which is attached to the GitHub release with the SBOM. NuGet.org adds a repository signature after upload, so a downloaded copy differs in bytes but not in content. `dotnet nuget verify` checks that signature.
