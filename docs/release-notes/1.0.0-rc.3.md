# RepoLore.Cli 1.0.0-rc.3 (release candidate, no author signature)

Third release candidate for 1.0.0. It settles the behaviors that scripts and agents rely on, so that 1.0.0 can keep them unchanged. They came out of a review of the field test's friction list (2026-10-25): each item below would have been a breaking change after 1.0.0.

## Install

```text
dotnet new tool-manifest
dotnet tool install RepoLore.Cli --version 1.0.0-rc.3 --local
```

A .NET 10 SDK is needed to install and a .NET 10.0.x runtime to run. See the [user guide](../user-guide.md). From an earlier candidate, change the version in `.config/dotnet-tools.json` and run `dotnet tool restore`; the knowledge format, the history and the method are unchanged. Check first that no `.repoloreignore` or `history.exclude` rule ends with a space: such a rule is now refused, and in `history.exclude` it blocks writes until you remove the space.

## Changes since 1.0.0-rc.2

- **Changed:** `tree` lists only Markdown notes and the folders that lead to one, each folder followed by its contents. It no longer lists other files, symlinks, folders without a note or `repolore.json`, and no longer lists all of a folder's children before any grandchild.
- **Changed:** checkpoint times have six fractional digits instead of seven, which Python before 3.11 could not parse. Older checkpoints are shown the same way.
- **Changed:** a `.repoloreignore` or `history.exclude` rule ending with a space or tab is invalid (`policy-error`). It used to match nothing, silently. Lines holding only whitespace are blank.
- **Changed:** `migrate --check --dry-run` is a usage error; use one of them.
- **Fix:** `init --update-method --json` reported `"checkpointId": null`; it now gives the checkpoint holding the new method, and the text output names it.
- **Testing:** scenarios tagged `contract` pin these decisions, and the ones kept as they are: the context budget's order, ignored unknown `repolore.json` keys, and exit 3 for a `restore --path` outside coverage. Four reference stages were added (`s43`–`s46`).

## Limits

- **No author signature.** NuGet.org adds only its own repository signature. Author signing is not planned for 1.0.0 (maintainer decision of 2026-10-24). This is not an enterprise-ready or certified release, and it makes no guarantee about what external editors or agents do with content they read.
- **Network evidence:** the networking-blocked run exists on Linux only, and there is no network-call trace.
- **Formats:** unknown knowledge formats are refused, and migration is explicit. The knowledge format is still 1.

## Verify

The publish run records the SHA-256 of the exact pushed package and of its SBOM in `RepoLore.Cli.1.0.0-rc.3.sha256`, which is attached to the GitHub release with the SBOM. NuGet.org adds a repository signature after upload, so a downloaded copy differs in bytes but not in content. `dotnet nuget verify` checks that signature.
