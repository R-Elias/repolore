# RepoLore 1.1.1 (no author signature)

The NuGet package is renamed from `RepoLore.Cli` to **`RepoLore`**, so the tool has the same name on every channel except npm (`repolore-cli`, since `repolore` there belongs to an unrelated project). The command is still `repolore`, and the code, its output and the knowledge format are the same as in 1.1.0.

## Install

```text
dotnet new tool-manifest
dotnet tool install RepoLore --version 1.1.1 --local
```

The other channels are unchanged: `curl -fsSL https://repolore.org/install.sh | sh`, `irm https://repolore.org/install.ps1 | iex`, `brew install repolore-org/tap/repolore`, `winget install repolore`, `pipx install repolore` or `npm install -g repolore-cli`. See the [user guide](../user-guide.md).

## Upgrading

- **From `RepoLore.Cli` (any version):** remove the old entry from the manifest and add the new one. Both packages provide the `repolore` command, and `dotnet tool` accepts both in one manifest, then silently runs one of them, so do not just add `RepoLore`:

  ```text
  dotnet tool uninstall RepoLore.Cli --local
  dotnet tool install RepoLore --version 1.1.1 --local
  ```

  Commit the changed `.config/dotnet-tools.json`. The knowledge format, the history and the method are unchanged, so there is nothing to migrate.
- **Native executables (PyPI, npm, Homebrew, winget, the install scripts):** upgrade as usual; nothing changes but the version.

Published `RepoLore.Cli` versions stay installable, so existing pins keep working, but they are deprecated in favor of `RepoLore` and receive no new versions. Everything listed as stable in 1.x in the [1.0.0 notes](1.0.0.md) still holds.

## Changes since 1.1.0

- **NuGet package renamed** to `RepoLore`. Its SBOM is now `RepoLore.1.1.1.cdx.json`.

## Limits

The limits of [1.1.0](1.1.0.md) still apply: no author signature on the NuGet package, no code signature on the executables, glibc Linux builds only (no musl), macOS 12 or later, and networking-blocked evidence on Linux x64 only.

## Verify

Download `repolore-1.1.1.sha256` from this release and check the files you downloaded with `shasum -a 256 -c --ignore-missing repolore-1.1.1.sha256` (or `sha256sum -c --ignore-missing repolore-1.1.1.sha256`). The wheels and npm packages are listed in `repolore-1.1.1.packages.sha256`. NuGet.org adds a repository signature after upload, so a package downloaded from it differs in bytes from the pushed file; `dotnet nuget verify` checks that signature.
